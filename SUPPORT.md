# Getting help

For experiences, lessons, and teaching material, start at
[foundin.space](https://foundin.space/). For code and data, use the
[project guide](https://github.com/Found-in-Space/.github/blob/main/docs/projects.md)
and the owning repository's README and examples.

## Questions, bugs, and ideas

Search the relevant repository's issues first. Open a new issue there if your
question is not covered. Use a bug, improvement, or scientific/data concern
form when it fits; a blank issue is fine for a question.

Include what you are trying to do, the package or application version, the
relevant environment, and a small reproducible example where possible. For data
or model questions, give the source, dataset version, identifiers, assumptions,
and a reference result if you have one. You do not need to know the cause to
report a problem.

If you cannot identify the owning project, ask in
[Found-in-Space/.github issues](https://github.com/Found-in-Space/.github/issues).
This is also the place to report a broken link in the organisation profile or
a gap in the shared documentation.

Project maturity varies. Check the owning repository for release status and
limitations. Support happens through the project maintainers; no response time
or service-level commitment is promised by these shared documents.

## Private concerns

- **Software vulnerabilities:** follow the
  [security policy](https://github.com/Found-in-Space/.github/blob/main/SECURITY.md).
- **Harassment or other conduct concerns:** follow the
  [code of conduct](https://github.com/Found-in-Space/.github/blob/main/CODE_OF_CONDUCT.md).

Both have a private contact at
[found-in-space@k-si.com](mailto:found-in-space@k-si.com). Keep ordinary technical
questions in public issues so the answer can help other people. Remove tokens,
private addresses, and personal information from examples and logs.
