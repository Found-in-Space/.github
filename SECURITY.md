# Reporting a security vulnerability

For a potential software vulnerability, email
[found-in-space@k-si.com](mailto:found-in-space@k-si.com).
Please keep vulnerability details and exploit examples out of public issues
and pull requests while the report is being investigated.

If the affected repository offers **Security → Report a vulnerability**, you
can use that private GitHub route instead. Availability is configured per
repository; this policy does not enable it automatically. A repository's own
security policy takes precedence over this shared default.

Include the affected repository and version or commit, a description of the
possible impact, and the smallest safe reproduction you can provide. Describe
any relevant configuration. Do not send live credentials, personal data, or
unnecessary copies of affected data.

Maintainers will use the private conversation to assess the report and discuss
remediation and disclosure. This shared policy does not promise a response
deadline or maintenance for particular release lines; check the affected
repository for any explicit support commitments.

Scientific inaccuracies, unexpected visual results, and ordinary bugs can be
reported publicly through the owning repository's issues, unless the report
also reveals a vulnerability or sensitive information.
