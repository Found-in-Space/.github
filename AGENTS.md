# Editing the Found in Space GitHub entry point

This public repository owns the organisation profile and default community
documents. Read `README.md`, `profile/README.md`, and `docs/projects.md` before
changing its structure or positioning.

- Preserve the mission: scientific data and models are materials people can
  explore, question, and build with. Reusable tools matter alongside experiences.
- Write the profile for developers and contributors, with a clear route to the
  public website for experiences, lessons, and teaching material.
- Keep the full project map in `docs/projects.md`. Verify current public
  repository identities and product capabilities before updating it. Do not
  infer publication from a local checkout, package name, or intended GitHub URL.
- Aeolian Measure may be described as in private development. Do not include its
  private repository URL or imply that its source is publicly available.
- Keep these documents self-contained. Do not link private planning documents,
  expose credentials, or include machine-specific paths.
- Place the organisation profile at `profile/README.md`, issue forms and their
  configuration at `.github/ISSUE_TEMPLATE/`, and the PR template at
  `.github/PULL_REQUEST_TEMPLATE.md`. Root community files provide defaults.
- Use absolute public links in the profile, inherited community documents, and
  templates. Use relative links within this repository's maintenance documents.
- Keep templates usable across libraries, applications, data pipelines, and
  documentation. Do not require labels, assignees, tools, or validation commands
  that have not been configured across repositories.
- Use `found-in-space@k-si.com` for private security and conduct reports. Do not
  invent response deadlines, supported-version guarantees, or reporting teams.
- Follow each product's own licence, notices, and contribution rules. This
  repository does not establish a blanket licence for the organisation's data,
  code, or third-party artwork.
- Check Markdown links, project coverage, YAML syntax, and `git diff --check`
  after edits. No product build or dataset regeneration is needed for these docs.
